# BNN 计算核心

`bnn_core/bnn_core_top.sv` 是与总线无关、单时钟、单在途任务的 W1A8 分组整数点积核心。
当前不含总线从接口、DMA、地址生成、激活存储、权重存储、FP16 scale 或浮点后处理。
协处理器和外挂设备可以复用此核心，由外层负责接入、数据调度及结果写回。

## 运算与规模

本版固定支持 `P_LANES=32`、`ACT_WIDTH=8`、`PSUM_WIDTH=16`、`RES_WIDTH=32`。
参数仍保留在模块声明中，但不支持其他取值，顶层和加法树在仿真初始化时报错。
加法树结构和各级位宽是固定的，不能通过覆盖参数改变物理结构。

一次命令处理一个输入向量和 N 个输出通道：

- `K = cmd_k_blocks * 32`。
- `G = cmd_group_div * 32`。
- `N = cmd_out_chans`。
- `groups = cmd_k_blocks / cmd_group_div`。
- `D[n][g] = sum(X[k] * W[n][k])`，k 遍历第 g 组。

激活按二补码 int8 解释，核心支持完整范围 `[-128, 127]`；权重位 1 表示 +1，0 表示 -1。
条件取负前先扩为 9 位，因此 `-(-128)=128` 不溢出。
每拍最多处理 32 个乘积；每个逻辑组输出一个 int32 结果。
最大组大小为 `255*32=8160`，组结果绝对值不超过 `8160*128=1044480`，int32 足够。

合法命令必须满足：

1. 三个命令尺寸均非零。
2. `cmd_k_blocks % cmd_group_div == 0`，只支持完整组。
3. `groups <= 256`，与 8 位组编号一致。

配置合法性由外层在提交命令前保证；核心只保留仅仿真 assert 检查上述约束，不提供运行时配置错误码或错误完成通道。
非法配置不属于可恢复的核心接口事务，测试应通过预期 assert 失败的独立探针验证，而非等待错误结果。
例如软件当前 G=128，对应 `cmd_group_div=4`。本核心没有 batch 维度，多个输入向量由外层分次提交。

## 命令与完成

所有信号都属于 `clock` 时钟域。`reset` 是高有效同步复位；外部跨时钟由适配层完成。
核心只有命令、共用输入和结果三个 ready-valid 通道，没有独立完成通知或取消接口。

| 信号 | 方向 | 含义 |
| --- | --- | --- |
| `cmd_valid / cmd_ready` | 输入 / 输出 | 上升沿二者同时为 1 时锁存三个尺寸并启动任务 |
| `cmd_k_blocks[15:0]` | 输入 | 每输出通道的物理块数 |
| `cmd_group_div[7:0]` | 输入 | 每逻辑组的物理块数 |
| `cmd_out_chans[15:0]` | 输入 | 输出通道数 |
| `status_idle` | 输出 | 状态机处于 IDLE；是否能接命令仍以 `cmd_ready` 为准，复位期间不能握手 |
| `status_busy` | 输出 | 状态机处于 RUN 或 DRAIN，正在收数或等待结果排空 |

命令尺寸只在 `cmd_valid && cmd_ready` 的上升沿采样，运行中改变输入尺寸不影响当前任务。
发送方在命令阻塞时须保持 valid 和命令字段，不能将 valid 当作无确认的启动脉冲。

状态顺序为 `IDLE -> RUN -> DRAIN -> IDLE`：

- IDLE 接收命令并启动任务；命令握手后进入 RUN，开始接收输入。
- RUN 按共用输入握手计数；收齐 `cmd_k_blocks * cmd_out_chans` 拍后进入 DRAIN。
- DRAIN 不再收输入，等待整个任务最后一个结果握手后返回 IDLE。
- 本版没有命令队列，不支持在最后结果握手的同一个上升沿接收下一命令；返回 IDLE 后，下一上升沿才可接收新命令。

`res_valid && res_ready && res_last` 是唯一成功完成条件。仅灌完输入、生成最后结果或将其写入输出缓冲均不算成功完成。
此条件只表示**核心输出已被下游接收**。设备层如还有 DMA 写回，必须等待写回真正完成后再向主机报告任务完成。

## 共用输入流

`act_data` 和 `weight_data` 共用一组 `in_valid / in_ready`，构成同一拍的两个操作数。
仅在上升沿 `in_valid && in_ready` 时同时接收激活和权重，不存在双输入独立握手。

| 信号 | 方向 | 含义 |
| --- | --- | --- |
| `in_valid / in_ready` | 输入 / 输出 | 一拍激活和权重的共用握手 |
| `act_data[255:0]` | 输入 | 32 个二补码 int8 激活 |
| `weight_data[31:0]` | 输入 | 32 个二值权重位 |

- lane i 对应 `act_data[i*8 +: 8]` 和 `weight_data[i]`。
- 每个输出通道按 k 递增提供 `cmd_k_blocks` 拍，然后开始下一个输出通道。
- 输入无 last 信号；物理块、逻辑组及通道边界均由锁存尺寸和已握手拍数推导。
- `in_valid && !in_ready` 时，发送方必须保持 `in_valid`、`act_data` 和 `weight_data` 稳定。
- 发送方必须独立于 ready 产生 valid，不能等待 ready 再拉高 valid。

目前没有内部激活缓存：对每个输出通道，外层必须重放一次相同的激活向量。
不要把这种重放直接变成重复主机上传。后续设备调度层应缓存激活并在本地供数，
必要时分别缓冲激活和权重以吸收独立访存延迟，再在外层配齐为共用输入拍。

## 结果流

结果按照 `[channel][group]` 顺序输出，通道递增、组递增；每个通道的组编号从 0 开始。
每个成功任务恰好产生 `N * groups` 个结果。第一版不携带通道 ID，由下游按固定顺序计数。

| 信号 | 含义 |
| --- | --- |
| `res_valid / res_ready` | 标准结果握手 |
| `res_data[31:0]` | 有符号组整数点积 |
| `res_group_idx[7:0]` | 当前通道内的组编号，0 到 groups-1 |
| `res_chan_last` | 当前结果是该输出通道的最后一组 |
| `res_last` | 当前结果是整个命令的最后一个结果，同时必有 `res_chan_last=1` |

结果接口不变，不提供 `res_error` 或运行时错误码。
正常运行时，阻塞期间 res_valid 和整个结果负载保持稳定；最后结果同样必须保持到握手，不能仅凭 res_last 置位判定完成。
输出使用双寄存器弹性缓冲，其输入 ready 由缓冲状态决定，切断从外部 res_ready 回到输入源的组合反压路径。
无停顿且每组一拍时可持续每周期输入一对操作数、输出一个结果；更大的组按组大小降低结果速率。

## 复位与外层恢复

`reset` 高有效同步：有效上升沿清空全部锁存配置、任务计数以及各流水级和输出缓冲的数据有效位，返回 IDLE。
reset 置位期间屏蔽所有握手，`cmd_ready`、`in_ready` 和 `res_valid` 均为 0。
复位会丢弃活动任务及尚未接收的结果，不产生取消通知；由复位撤销结果 valid 是正常阻塞稳定性规则的例外。

复位前可能已有部分结果被外部接收，这些写入不能撤回，外层必须将被复位任务的整个结果区视为无效。
外层同时负责清理输入源，丢弃未消费的旧数据，在下个命令前恢复到新任务起点；下游不得继续等待旧任务的 res_last。
核心不带 epoch/tag，无法识别外层在新命令后继续送来的旧任务数据。
除复位外，核心没有任务取消或运行时错误通知路径；外层若发现超时或结果协议异常，应自行复位并报告软件错误。

## 软件接入边界

本核心实现 `BNN_OP_DOT_GROUPS` 的算术部分。现有引擎 runtime 调用 GEMV/GEMM，要求 float 输出，
因此不能直接将本核心结果当作完整 GEMV/GEMM 返回。
硬件后端需要在 CPU 或设备后处理层执行 FP16 scale 到 FP32 的转换、每组乘法和按组顺序的 FP32 累加。
具体舍入和禁用 FMA 的要求见 `bnn-accelerator/bnn-accelerator.h`。
公共软件 API 对 -128 的拒绝、内存范围检查、数据布局和字节序适配也由后端负责。

目前已接入 `ACCE=verilator`：`verilator-bnn-accelerator.c` 实现公共 API，
`verilator-bnn-bridge.cpp` 通过 C ABI 封装生成的模型，逐周期驱动本核心。
每个设备拥有自己的 `VerilatedContext` 和模型；GEMM 按输入行提交任务，激活在桥接层按输出通道重放。
桥接层提交前检查配置，同时供数和收数，校验结果数量、组编号及边界标志，推进最后结果握手的时钟沿后，再核对收发计数及 `cmd_ready` 才返回成功，不额外等待完成周期。
超时或桥接层检测到异常会复位模型并作废部分结果；默认周期预算由任务规模推导，桥接测试也可传入较小预算验证超时恢复。
这些软件错误码由外层产生，并非核心错误通知。这只是进程内功能仿真，不模拟 DMA、总线延迟和真实存储带宽。构建和后端差分测试见仓库根 README。

波形默认关闭。设置 `BNN_RTL_TRACE_DIR` 为已有可写目录后，每个新设备创建一个唯一的 VCD，
记录复位、顶层和内部流水信号以及该设备上的所有计算任务；任务结束后刷新，关闭设备时完成文件。
默认模型已编译 tracing 支持，无需为每次调试重新构建。
时间单位为 1ps、时钟周期为 10ns，仅用于波形查看，不代表实现频率。
可运行 `make -C tests/trace waves` 生成小型 DOT/GEMV 波形，
或运行 `make -C tests/trace test` 只进行专项检查并自动清理临时文件。

## 测试

在仓库根目录执行：

```sh
make -C bnn-hw/bnn_core_test test
make -C bnn-hw/bnn_core_test lint
```

测试采用 SystemVerilog 自检 testbench 和 Verilator，无需 cocotb 或 Python 虚拟环境。
测试构建产物写入仓库的 `build/bnn-core-test/`，不写入 RTL 目录。
默认运行 seed 1、7、42，每个 seed 执行定向用例和 16 个随机任务，日志为 `build/bnn-core-test/seed-<seed>.log`。
`test` 还通过独立探针验证不支持的结构参数和非法配置会被仿真断言显式拒绝；探针必须运行到预期 assert 失败，非零退出是预期结果，编译失败不算通过。
非法配置探针覆盖三个尺寸非零、整除和 `groups <= 256`，不再期待运行时错误码或错误完成握手。

增加随机任务或复现特定 seed：

```sh
make -C bnn-hw/bnn_core_test test SEEDS="7 42" RANDOM_CASES=64
```

可使用 `JOBS=<并行编译数>` 控制首次编译的资源占用，使用 `MAX_CYCLES=<周期数>` 调整全局超时。
定向用例覆盖精确点积、lane 顺序、多组多通道、最大合法 K、最大通道数、组编号 255、
共用输入停顿、随机输出反压、每周期吞吐、最后结果阻塞保持、完成后下一沿接命令和复位恢复。
参考模型只读取顶层握手和负载，不读取内部计数器或流水线状态。
